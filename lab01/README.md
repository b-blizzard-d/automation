# Лабораторная работа №1

**Тема:** автоматизация резервного копирования каталогов с помощью bash-скрипта.
**Студентка:** Метельская Даниела, вводный курс Linux, USM.

## Задание

Написать скрипт `backup.sh`, который создаёт резервную копию указанного каталога.

1. Первый аргумент скрипта: путь к каталогу, который нужно сохранить (обязательный).
2. Второй аргумент: каталог, куда будет сохранена резервная копия (необязательный,
   по умолчанию `/backup`).
3. Скрипт создаёт архив формата `tar.gz`, в имени которого есть текущая дата.
4. Скрипт проверяет, что оба каталога существуют, и при ошибке выводит понятное сообщение.

## Описание работы скрипта

Скрипт линейный, без функций. Каждый шаг в коде отмечен комментарием с тем же номером,
что и в этом списке:

1. **Проверка аргументов.** Если скрипт запущен без аргументов, он выводит в stderr сообщение
   об ошибке и строку с подсказкой по использованию, затем завершается с кодом `1`.
2. **Каталог назначения.** Второй аргумент берётся через `${2:-/backup}`: если он не указан,
   используется `/backup`.
3. **Проверка существования каталогов.** С помощью `[ -d ... ]` проверяется сначала
   каталог-источник, потом каталог назначения. Если какого-то из них нет, выводится ошибка
   и скрипт завершается с кодом `1`. Каталог назначения скрипт сам **не создаёт**.
4. **Формирование имени архива.** Из пути выделяются родительский каталог (`dirname`) и имя
   каталога (`basename`), берётся текущая дата командой `date +%Y-%m-%d_%H-%M`.
   Имя архива строится по шаблону `<имя_каталога>_backup_<ГГГГ-ММ-ДД_ЧЧ-ММ>.tar.gz`,
   например `documents_backup_2026-10-26_15-30.tar.gz`.
5. **Создание архива.** Выполняется команда
   `tar -czf "<назначение>/<имя_архива>" -C "<родительский_каталог>" "<имя_каталога>"`.
   Благодаря ключу `-C` в архив попадает только сам каталог (`documents/...`), а не полный
   путь от корня. Затем проверяется код завершения `$?`: если tar завершился с ошибкой,
   выводится `Ошибка при создании архива.` и скрипт завершается с кодом `1`.
6. **Результат.** Выводится путь к созданному архиву и его размер (`du -h ... | cut -f1`).

Коды выхода:

| Код | Значение |
|-----|----------|
| `0` | архив успешно создан |
| `1` | ошибка: нет аргумента, нет каталога или tar не смог создать архив |

## Требования

- интерпретатор `bash` (подойдёт любая современная версия, запускался на macOS и в Ubuntu);
- `tar` и `gzip` (есть в любой стандартной установке Linux);
- стандартные утилиты `date`, `dirname`, `basename`, `du`, `cut`.

## Установка

Скрипт находится в каталоге `lab01`. Перед первым запуском нужно разрешить его выполнение:

```bash
cd lab01
chmod +x backup.sh
```

В репозитории файл уже сохранён с правами на выполнение, поэтому после `git clone`
этот шаг обычно не нужен.

## Использование

```
./backup.sh <каталог> [каталог_назначения]
```

- `<каталог>`: каталог, который нужно сохранить;
- `[каталог_назначения]`: куда положить архив; если не указан, используется `/backup`.

Типичные вызовы:

```bash
./backup.sh /home/daniela/documents              # архив попадёт в /backup
./backup.sh /var/www/html /srv/archive           # архив попадёт в /srv/archive
```

## Примеры

Все примеры ниже получены при реальном запуске скрипта в тестовой папке, где лежали
каталог `documents` (с файлами `linux.txt` и `notes/todo.txt`) и пустой каталог `archive`.
Дата и время в имени архива будут соответствовать моменту вашего запуска.

### Пример 1. Обычный запуск с указанием каталога назначения

```
$ ./backup.sh documents archive
Резервная копия успешно создана: archive/documents_backup_2026-10-24_17-02.tar.gz
Размер архива: 4.0K
$ echo $?
0
```

> **Примечание.** Формат размера зависит от локали системы: в русской локали `du`
> может вывести `4,0K` (с запятой), в английской `4.0K` (с точкой).

### Пример 2. Запуск без второго аргумента (каталог по умолчанию `/backup`)

Если каталога `/backup` в системе нет, скрипт сообщает об этом и ничего не создаёт:

```
$ ./backup.sh documents
Ошибка: каталог назначения "/backup" не существует. Создайте его вручную.
$ echo $?
1
```

После `sudo mkdir -p /backup` (и выдачи прав на запись) архив будет создан в `/backup`.

### Пример 3. Несуществующий каталог-источник

```
$ ./backup.sh nonexistent
Ошибка: каталог-источник "nonexistent" не найден.
$ echo $?
1
```

### Пример 4. Несуществующий каталог назначения

```
$ ./backup.sh documents no_such_dir
Ошибка: каталог назначения "no_such_dir" не существует. Создайте его вручную.
$ echo $?
1
```

### Пример 5. Запуск без аргументов

```
$ ./backup.sh
Ошибка: не указан каталог для резервного копирования.
Использование: ./backup.sh <каталог> [каталог_назначения]
$ echo $?
1
```

## Возможные ошибки

| Сообщение | Причина | Что сделать |
|-----------|---------|-------------|
| `Ошибка: не указан каталог для резервного копирования.` | скрипт запущен без аргументов | указать каталог: `./backup.sh <каталог>` |
| `Ошибка: каталог-источник "..." не найден.` | опечатка в пути или каталог удалён | проверить путь командой `ls -d <каталог>` |
| `Ошибка: каталог назначения "/backup" не существует. Создайте его вручную.` | каталог по умолчанию `/backup` не создан | выполнить `sudo mkdir -p /backup` или указать другой каталог вторым аргументом |
| `Ошибка: каталог назначения "..." не существует. Создайте его вручную.` | указанного каталога назначения нет | создать его: `mkdir -p <каталог>` |
| `Ошибка при создании архива.` | tar не смог записать архив (например, нет прав на запись) | проверить права: `ls -ld <каталог_назначения>`; для `/backup` запустить скрипт от имени администратора (`sudo`) |

Пример последней ошибки (каталог назначения доступен только для чтения), сообщение `tar:`
выводит сама утилита tar (в Linux его текст будет немного другим):

```
$ ./backup.sh documents readonly
tar: Failed to open 'readonly/documents_backup_2026-10-24_17-02.tar.gz'
Ошибка при создании архива.
$ echo $?
1
```

## Проверка результата

Содержимое архива можно посмотреть, не распаковывая его, командой `tar -tzf`:

```
$ tar -tzf archive/documents_backup_2026-10-24_17-02.tar.gz
documents/
documents/linux.txt
documents/notes/
documents/notes/todo.txt
```

Видно, что в архиве хранится только каталог `documents` с его содержимым, без полного пути.
Чтобы восстановить данные, архив распаковывают в нужное место:

```bash
tar -xzf archive/documents_backup_2026-10-24_17-02.tar.gz -C /куда/распаковать
```

В ходе работы был написан bash-скрипт для резервного копирования каталога. Скрипт проверяет
входные данные, сообщает об ошибках в stderr с ненулевым кодом выхода, создаёт сжатый архив
`tar.gz` с датой и временем в имени и выводит размер полученного архива.
